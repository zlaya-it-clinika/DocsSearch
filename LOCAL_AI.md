# Подключение локальной ИИ для тестирования

Инструкция для Windows. Всё работает только на вашем компьютере: документы и вопросы никуда не уходят.

## Что сейчас делает ИИ в проекте

| Часть | Модель | Статус в `API_MODE=live` |
|---|---|---|
| Индексация документов: текст режется на фрагменты, для каждого считается вектор | `nomic-embed-text` | работает |
| Поиск похожих фрагментов в PostgreSQL (pgvector) с учётом уровня доступа | `nomic-embed-text` для вектора вопроса | работает |
| Ответ в чате: пересказ по найденным фрагментам, цитаты, процент релевантности | `OLLAMA_CHAT_MODEL`: `vikhr-nemo` (Vikhr-Nemo-12B) | работает |
| Уточняющий вопрос: если два лучших фрагмента из разных документов почти одинаково подходят, модель спрашивает, о каком документе речь | `OLLAMA_CHAT_MODEL` | работает |
| Честный отказ: если подходящих фрагментов нет, ответ `fallback` без обращения к модели | - | работает |
| Бланки и проверка черновика | - | пока заглушки ядра |

Для проверки нужны обе модели: без них чат отвечает ошибкой «Локальная модель ИИ недоступна».

## Что понадобится

- Windows 10 или 11, от 16 ГБ оперативной памяти. Vikhr-Nemo-12B в квантизации Q4_K_M занимает около 8 ГБ памяти при работе, с видеокартой от 8 ГБ отвечает в разы быстрее
- около 10 ГБ на диске под модели
- Docker Desktop (для PostgreSQL)
- Go 1.24 или новее (для запуска ядра)
- Node.js 22 или новее (для веба)

## Шаг 1. Установить Ollama

Ollama - программа, которая запускает модели локально и отдаёт их по адресу `http://127.0.0.1:11434`.

```bash
winget install -e --id Ollama.Ollama
```

Или скачать установщик с ollama.com. После установки Ollama работает в фоне, значок появляется в трее.

Проверка: в новом окне терминала

```bash
ollama --version
```

```bash
curl http://127.0.0.1:11434/api/version
```

Должна прийти строка вида `{"version":"..."}`.

## Шаг 2. Скачать модели

Модель эмбеддингов. Нужна именно она: база создана под векторы длиной 768.

```bash
ollama pull nomic-embed-text
```

Чат-модель проекта - [Vikhr-Nemo-12B-Instruct-R-21-09-24](https://huggingface.co/Vikhrmodels/Vikhr-Nemo-12B-Instruct-R-21-09-24): Mistral-Nemo 12B, обученная на русском, лицензия Apache-2.0. Ollama берёт её готовую квантизацию в формате GGUF прямо с Hugging Face. Параметры генерации заданы в [source/ollama/vikhr-nemo.Modelfile](source/ollama/vikhr-nemo.Modelfile): авторы модели советуют temperature 0.1-0.5, а ядро своих параметров не передаёт.

Из корня репозитория:

```bash
ollama pull hf.co/bartowski/Vikhr-Nemo-12B-Instruct-R-21-09-24-GGUF:Q4_K_M
```

```bash
ollama create vikhr-nemo -f source/ollama/vikhr-nemo.Modelfile
```

Проверка: `ollama run vikhr-nemo "Кратко: что такое входящий документ?"` отвечает по-русски. В `.env` ядра: `OLLAMA_CHAT_MODEL=vikhr-nemo`.

Другая квантизация: заменить `Q4_K_M` в обеих командах и в Modelfile. `Q5_K_M` (8 ГБ) точнее, `IQ4_XS` (6 ГБ) легче. Список файлов: репозиторий `bartowski/Vikhr-Nemo-12B-Instruct-R-21-09-24-GGUF` на Hugging Face.

### Своя дообученная версия Vikhr

Ollama запускает модели в формате GGUF. После дообучения:

1. Если обучали LoRA-адаптер, слить его с базовой моделью (например, `merge_and_unload()` в PEFT) и сохранить в safetensors.
2. Перевести в GGUF и квантовать инструментами llama.cpp:

```bash
python convert_hf_to_gguf.py путь/к/модели --outfile vikhr-docs-f16.gguf
```

```bash
llama-quantize vikhr-docs-f16.gguf vikhr-docs-Q4_K_M.gguf Q4_K_M
```

3. Положить `vikhr-docs-Q4_K_M.gguf` в `source/ollama` и поменять в `vikhr-nemo.Modelfile` первую строку `FROM` на `FROM ./vikhr-docs-Q4_K_M.gguf`.
4. Пересоздать модель: `ollama create vikhr-nemo -f source/ollama/vikhr-nemo.Modelfile`. Имя `vikhr-nemo` остаётся прежним, поэтому `.env` ядра менять не нужно.

Файлы `.gguf` весят гигабайты, в git их не кладём: передавайте через общий диск.

Проверка эмбеддингов: команда ниже должна вывести `768`.

```bash
curl -s http://127.0.0.1:11434/api/embed -d "{\"model\":\"nomic-embed-text\",\"input\":[\"проверка\"]}" | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(JSON.parse(s).embeddings[0].length))"
```

Шаги 3-5 можно заменить одной командой: общий `docker compose` в каталоге `source` поднимает PostgreSQL, ядро и веб сразу, а с профилем `ollama` и саму Ollama с моделями. Инструкция в [source/README.md](source/README.md). Ниже - запуск по отдельности, удобный для разработки.

## Шаг 3. Запустить PostgreSQL

```bash
cd source/core
docker compose up -d postgres
```

Проверка: `docker compose ps` показывает `postgres` в состоянии `healthy`.

## Шаг 4. Запустить ядро в боевом режиме

В `source/core` скопировать `.env.example` в `.env` и поменять в нём:

```
API_MODE=live
DOCS_PASSWORD=любой-пароль
DATABASE_URL=postgres://docs:docs@localhost:5432/docssearch?sslmode=disable
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_CHAT_MODEL=vikhr-nemo
OLLAMA_EMBED_MODEL=nomic-embed-text
OLLAMA_EMBED_DIMENSIONS=768
```

Запуск из `source/core`:

```bash
go run ./cmd/api
```

При первом запуске Go скачает зависимости, это может занять несколько минут. Ядро готово, когда в логе с `DEBUG=true` появится строка `listen :8080 mode live`. Таблицы в базе создаются сами. Учётных записей нет: первый, кто откроет сайт, создаёт администратора.

Вариант целиком в Docker: `docker compose up -d --build` в `source/core`. Ядро в контейнере обращается к Ollama на хосте через `host.docker.internal:11434`. Если сборка падает на `apk add` с `temporary error`, см. раздел «Если что-то не работает».

## Шаг 5. Запустить веб

```bash
cd source/web
cp .env.example .env
npm start
```

В `.env` веба должно быть `CORE_API_URL=http://localhost:8080`. Открыть `http://localhost:3000`.

## Шаг 6. Загрузить документы в базу знаний

1. При первом открытии сайта создать учётную запись администратора: имя, почта, пароль. Если сайт уже открывали, войти под этой учётной записью.
2. Меню пользователя внизу слева → «Админ-панель» → вкладка «База знаний».
3. «Загрузить» → выбрать файл из `source/docs`.
4. Заполнить «Редакция» (например, `1.0`) и «Кому доступен»: «Все сотрудники» или «Только администраторы».
5. «Загрузить». Пока ядро считает векторы, кнопка неактивна. После успеха документ появляется в списке.

Повторная загрузка файла с тем же названием заменяет актуальную редакцию.

Проверка, что фрагменты легли в базу (из `source/core`):

```bash
docker compose exec postgres psql -U docs -d docssearch -c "SELECT d.title, count(c.*) AS fragments FROM documents d LEFT JOIN chunks c USING (document_id) GROUP BY d.title"
```

Проверка доступа: зарегистрировать второго сотрудника на экране входа, в «Админ-панель» → «Пользователи» нажать на его роль «Ожидает», чтобы стала «Пользователь», и войти под ним. Документы «Только администраторы» не видны ни в списке «Документы», ни по ссылке.

## Настройка из админ-панели

После первого запуска всё, что выше задано в `.env`, можно менять на сайте: админ-панель, вкладка «Модели ИИ». Нужен флаг «Модели ИИ» (`ai.manage`), он есть у главного администратора и администратора.

- «Подключение к Ollama»: адрес сервера и кнопка «Проверить» - показывает версию Ollama или «Нет связи». В Docker адрес `http://ollama:11434` (профиль `ollama`) или `http://host.docker.internal:11434` (Ollama на этом компьютере)
- «Модели»: какая модель отвечает в чате и какая строит векторы для поиска. Список берётся из Ollama, модель из настроек, которой там нет, помечена «не скачана»
- «Параметры ответа»: температура, Top K, Top P, окно контекста. Пустое поле - значение из Modelfile модели
- «Скачанные модели»: скачать модель по имени из библиотеки Ollama или `hf.co/...` с ходом скачивания и кнопкой «Остановить», проверить ответ модели, удалить ненужную. Модель, на которой работают ответы или поиск, удалить нельзя
- «Индекс базы знаний»: после смены модели эмбеддингов кнопка «Переиндексировать» пересчитывает векторы всех фрагментов в фоне. Новая модель эмбеддингов принимается, только если её вектор того же размера, что `OLLAMA_EMBED_DIMENSIONS`

Сохранённые на сайте значения хранятся в базе и важнее `.env`. В `API_MODE=stub` вкладка тоже работает с настоящей Ollama по `OLLAMA_URL`, но настройки живут до перезапуска ядра, а переиндексации нет.

## Если что-то не работает

| Что видно | Причина и что сделать |
|---|---|
| «локальная модель эмбеддингов недоступна» (`embed_unavailable`) | Ollama не запущена, модель не скачана или неверный `OLLAMA_URL`. Проверить шаги 1 и 2. Большой PDF на слабом процессоре может не уложиться в минуту ожидания ядра: попробуйте сначала небольшой `.docx` |
| «вектор другого размера» (`embed_size_mismatch`) | Модель эмбеддингов отдаёт не 768 чисел. Вернуть `nomic-embed-text` или пересоздать базу под другой размер |
| «База данных ядра недоступна» (`store_unavailable`) | PostgreSQL не запущен или неверный `DATABASE_URL`. Шаг 3 |
| «Ядро недоступно» (`core_unavailable`) | Ядро не запущено или неверный `CORE_API_URL` в `.env` веба |
| «Этот формат не поддерживается» | Ядро принимает только `.txt`, `.pdf`, `.docx` |
| Docker-сборка ядра падает на `apk add ... temporary error` | Контейнеры не видят интернет по DNS. Docker Desktop → Settings → Docker Engine, добавить `"dns": ["8.8.8.8", "1.1.1.1"]`, Apply & restart. Или запускать ядро через `go run` (шаг 4) |
| Ядро в Docker не достаёт до Ollama | В переменных среды Windows задать `OLLAMA_HOST=0.0.0.0`, перезапустить Ollama из трея |
| Порт 8080 или 3000 занят | Остановить старый процесс или поменять `API_PORT` и `WEB_PORT` |

## Как проверить ответы чата

1. Загрузить документы из `source/docs` (шаг 6).
2. Открыть «Новый чат» и спросить своими словами, например: «Как зарегистрировать входящий документ?». Ответ придёт с источниками и процентом релевантности, клик по источнику показывает цитату и ссылку на оригинал.
3. Задать вопрос, который подходит к нескольким документам сразу, например: «Как оформить приказ?». Помощник должен уточнить, о каком документе речь. Ответ на уточнение уходит в тот же чат, контекст сохраняется.
4. Спросить о том, чего нет в документах, например: «Какой пароль от Wi-Fi?». Должен прийти честный отказ без выдуманных фактов.

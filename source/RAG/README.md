# Прототип RAG на Python

Консольный прототип, на котором команда проверяла идеи до переноса в ядро: нарезку инструкции по пунктам, пороги релевантности, двухшаговый ответ модели и заполнение модульных бланков. Сайт и ядро его **не используют**: рабочая версия всего этого живёт в [source/core](../core).

Ответственный: rodyaisdead.

## Что внутри

Скрипты идут по этапам:

| Скрипт | Этап | Что делает |
|---|---|---|
| `ingest.py` | 2 | разбирает материалы кейса из `docs/` и строит векторную базу в `data/` |
| `search.py` | - | поиск без модели: какие фрагменты найдутся по вопросу |
| `rag.py` | 3 | ответ на вопрос: поиск и Vikhr-Nemo в режиме Grounded RAG |
| `fill.py`, `templates.py` | 4 | подготовка приказа или распоряжения по модульному бланку в диалоге, маршрут визирования по Матрице |
| `check.py` | - | проверка оформления `.docx` по ГОСТ Р 7.0.97-2025 и Инструкции по ДОУ |
| `eval.py` | - | прогон 56 контрольных вопросов из `tests.json` и подсчёт точности |
| `extract.py`, `config.py` | - | извлечение текста и все настройки: модели, пороги, размер фрагмента |
| `test_vikhr.py` | - | проверка, что модель отвечает в формате Grounded RAG |

Как ответ защищён от выдумок (эти правила потом перешли в ядро):

1. Вопрос с низкой релевантностью получает отказ без обращения к модели (`MIN_SCORE`).
2. Модель сначала выбирает номера документов с ответом, затем отвечает только по ним.
3. Если модель ничего не выбрала, но поиск уверен (`FALLBACK_SCORE`), показывается ближайший пункт дословно.
4. К фрагментам добавляется справочник сокращений из п. 1.4 Инструкции, чтобы модель не расшифровывала их сама.

## Запуск

Нужны Python 3, [Ollama](https://ollama.com) и две модели из [config.py](config.py):

```bash
ollama pull bge-m3
ollama pull OxW/Vikhr-Nemo-12B-Instruct-R-21-09-24:q4_K_M
```

```bash
pip install numpy ollama pdfplumber python-docx
```

Из каталога `source/RAG`. Векторы (`data/vectors.npy`) в git не лежат, поэтому первым шагом:

```bash
python ingest.py
```

Дальше:

```bash
python rag.py "Когда регистрируются входящие документы?"
```

| Команда | Что делает |
|---|---|
| `python rag.py` | диалог в консоли, `--debug` показывает внутренние шаги и оценки |
| `python search.py "вопрос"` | что найдёт поиск, без модели |
| `python fill.py` | выбрать модуль и заполнить его в диалоге; `--demo` - тестовыми данными. Результат в `data/out/` |
| `python check.py файл.docx` | замечания по оформлению со ссылками на пункты |
| `python eval.py` | все контрольные вопросы; `--cat матрица` - одна категория, `--id 30 36` - отдельные. Итог в `data/eval_ДАТА.csv` |
| `python ingest.py --no-embed` | только нарезка, без Ollama |

Ollama на другом компьютере: поменять `OLLAMA_HOST` в `config.py`.

## Отличия от ядра

| | Прототип | Ядро |
|---|---|---|
| Модель эмбеддингов | `bge-m3` | `nomic-embed-text` по умолчанию, меняется в настройках |
| Хранение векторов | файл `vectors.npy` | PostgreSQL с pgvector |
| Порог отказа | `0.50` | `0.4` |
| Права доступа | нет | роли и личные документы |
| Пользователи | одна консоль | веб, админ-панель, виджет |

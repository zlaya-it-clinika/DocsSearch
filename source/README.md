# Запуск и обслуживание DocsSearch

Как поднять весь проект одной командой, настроить и держать его в рабочем состоянии. Все команды - из каталога `source`.

## Что запускается

| Сервис | Что это | Где доступен |
|---|---|---|
| `web` | чат, админ-панель, виджет | http://localhost:3000 |
| `api` | ядро на Go | внутри сети compose; страница ручных запросов http://127.0.0.1:8080/docs только с этой машины |
| `postgres` | PostgreSQL с pgvector: пользователи, чаты, документы, векторы | только внутри сети compose |
| `ollama`, `ollama-models` | Ollama в контейнере и однократная загрузка моделей | профиль `ollama` |
| `ldap` | тестовый каталог LLDAP | профиль `ldap`, см. [LDAP_DEMO.md](../LDAP_DEMO.md) |

Сотрудники открывают только `web`. Ядро и база наружу не открыты.

## Требования

- Docker Desktop (Windows, macOS) или Docker Engine с Compose v2 (Linux)
- Ollama на этой машине с моделями `nomic-embed-text` и `vikhr-nemo` ([LOCAL_AI.md](../LOCAL_AI.md), шаг 2) или профиль `ollama` ниже
- от 16 ГБ оперативной памяти и около 10 ГБ на диске под модели

## Запуск

1. Создать настройки и задать в них `DOCS_PASSWORD` (пароль страницы `/docs` ядра, без него compose не стартует):

   ```bash
   cp .env.example .env
   ```

2. Собрать и запустить. Первая сборка качает образы и занимает несколько минут:

   ```bash
   docker compose up -d --build
   ```

3. Проверить, что всё поднялось:

   ```bash
   docker compose ps
   ```

   У `postgres`, `api` и `web` должно быть `healthy`. Веб стартует после ядра, ядро - после базы.

4. Открыть http://localhost:3000 и создать первую учётную запись: она становится главным администратором со всеми правами.

## Первые шаги после запуска

1. Стандартный набор из [docs](docs) ядро загружает само при каждом запуске, векторы досчитываются в фоне. Свои документы: «Админ-панель» -> «База знаний» -> «Загрузить», здесь же выбираются процесс и роли, которым документ виден.
2. Сотрудники регистрируются по почте и ждут подтверждения в «Админ-панель» -> «Пользователи». Роль по умолчанию меняется в «Настройках».
3. Задать вопрос в чате. Сценарии проверки ответа, уточнения и честного отказа - в [LOCAL_AI.md](../LOCAL_AI.md#как-проверить-ответы-чата).

## Если Ollama на этой машине нет

Ollama запустится в контейнере, скачает модель эмбеддингов и Vikhr-Nemo-12B (около 8 ГБ) и соберёт `vikhr-nemo` из [ollama/vikhr-nemo.Modelfile](ollama/vikhr-nemo.Modelfile).

1. В `.env`: `OLLAMA_URL=http://ollama:11434`
2. Запуск с профилем:

   ```bash
   docker compose --profile ollama up -d --build
   ```

3. Ход загрузки моделей (сервис завершится сам):

   ```bash
   docker compose logs -f ollama-models
   ```

Модели лежат в томе `docssearch_ollama-models` и второй раз не качаются. На процессоре ответы заметно медленнее, чем у Ollama на хосте с видеокартой.

## Настройки `.env`

Полный список с комментариями - в [.env.example](.env.example). Чаще всего меняют:

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `DOCS_PASSWORD` | пароль страницы `/docs` ядра | обязателен |
| `API_MODE` | `live` - база и модель, `stub` - фиксированные ответы для проверки интерфейса | `live` |
| `WEB_PORT` | порт сайта на этой машине | `3000` |
| `OLLAMA_URL` | адрес Ollama | `http://host.docker.internal:11434` |
| `OLLAMA_CHAT_MODEL` | модель ответов | `vikhr-nemo` |
| `OLLAMA_EMBED_MODEL`, `OLLAMA_EMBED_DIMENSIONS` | модель эмбеддингов и длина её вектора | `nomic-embed-text`, `768` |
| `STANDARD_DOCS_PATH` | каталог стандартного набора документов | `./docs` |
| `LAYOUT_FORMAT_PRIORITY` | порядок правил оформления: пусто - Инструкция по ДОУ, `gost` - ГОСТ первым | пусто |
| `ENABLE_SIGNUP`, `DEFAULT_USER_ROLE` | регистрация и роль новых пользователей | `true`, `pending` |
| `ENABLE_LDAP`, `LDAP_*` | вход через каталог | выключен |
| `COOKIE_SECURE`, `COOKIE_SAMESITE` | cookie сессии, для HTTPS - `true` | `false`, `Lax` |
| `EMBED_ALLOWED_ORIGINS` | порталы, которым можно встраивать виджет | пусто |
| `DEBUG` | подробные логи ядра и веба | `false` |

Регистрация, LDAP и модели ИИ задаются в `.env` только как начальные значения. После сохранения в админ-панели действуют значения из базы.

Сменить модель эмбеддингов на модель с другой длиной вектора (например, `bge-m3`, 1024): поменять обе переменные и перезапустить. Ядро само перестроит индекс и пересчитает векторы в фоне, документы останутся.

## Вход через LDAP или Active Directory

«Админ-панель» -> «Настройки» -> «LDAP». Для Active Directory обычно:

- адрес контроллера домена, порт 636 и TLS
- DN служебной учётной записи только для чтения и её пароль
- атрибут логина `sAMAccountName`, атрибут почты `mail`
- база поиска, например `OU=Users,DC=corp,DC=local`
- фильтр только нужной группы и без отключённых учётных записей:
  `(&(memberOf=CN=DocsSearch,OU=Groups,DC=corp,DC=local)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))`

Сертификат CA компании: положить в `source/certs`, подключить к контейнеру `api` строкой `- ./certs:/certs:ro` в `volumes` и указать путь `/certs/<файл>.pem` в настройках.

Вход через каталог создаёт свою учётную запись по почте сотрудника. Если такая почта уже занята обычной учётной записью, вход через каталог в неё не пустит: это защита от захвата чужой учётной записи. Пошаговая проверка на тестовом каталоге - [LDAP_DEMO.md](../LDAP_DEMO.md).

## Повседневные команды

| Что сделать | Команда |
|---|---|
| Остановить, данные сохранятся | `docker compose down` |
| Запустить снова | `docker compose up -d` |
| Обновить после `git pull` | `docker compose up -d --build` |
| Логи всех сервисов | `docker compose logs -f` |
| Логи одного сервиса | `docker compose logs -f api` |
| Удалить вместе с базой и моделями | `docker compose --profile ollama down -v` |

С `-v` пропадают все документы, пользователи и чаты. Без `-v` они остаются в томах Docker.

## Если что-то не работает

| Что видно | Что сделать |
|---|---|
| `required variable DOCS_PASSWORD is missing a value` | задать `DOCS_PASSWORD` в `source/.env` |
| `port is already allocated` на 3000 или 8080 | порт занят: поменять `WEB_PORT` или `API_PORT_LOCAL` в `.env` |
| сборка падает на `apk add ... temporary error` | Docker не видит DNS. Docker Desktop -> Settings -> Docker Engine, добавить `"dns": ["8.8.8.8", "1.1.1.1"]`, Apply & restart |
| в чате «Локальная модель ИИ недоступна» | Ollama не запущена, модели не скачаны или неверный `OLLAMA_URL`: для Ollama на хосте `http://host.docker.internal:11434`, для профиля `http://ollama:11434` |
| ядро в Docker не достаёт до Ollama на Windows | задать переменную среды Windows `OLLAMA_HOST=0.0.0.0` и перезапустить Ollama из трея |
| «вектор другого размера» | `OLLAMA_EMBED_DIMENSIONS` не совпадает с моделью: 768 для `nomic-embed-text`, 1024 для `bge-m3` |
| `web` не становится `healthy` | `docker compose logs api`: веб ждёт, пока ответит ядро |
| нет экрана создания администратора | в базе уже есть пользователи. Начать с чистой базы: `docker compose down -v` (удалит все данные) |

## Отдельный запуск модулей

У ядра и веба есть свои compose: [core/docker-compose.yml](core/docker-compose.yml) (ядро и PostgreSQL) и [web/docker-compose.yml](web/docker-compose.yml) (только веб). Они нужны для разработки одного модуля, общий compose их не использует. Запуск без Docker - в [LOCAL_AI.md](../LOCAL_AI.md#шаг-3-запустить-postgresql).

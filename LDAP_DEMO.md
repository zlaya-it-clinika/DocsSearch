# Проверка входа через LDAP и запись демо

Вход через каталог проверяется на тестовом сервере LLDAP: это настоящий LDAP-сервер с веб-интерфейсом, ядро ходит к нему так же, как к Active Directory компании. Сотрудников и группы в нём создают руками, поэтому их удобно показывать на видео.

Сценарий проверен на `source/docker-compose.yml`: вход по логину и паролю каталога, отказ при неверном пароле, ожидание подтверждения без группы и мгновенный доступ с группой.

## 1. Запустить каталог

В `source/.env` задать пароль администратора каталога (от 8 символов) и два секрета. Секреты - любые длинные случайные строки:

```bash
openssl rand -hex 32
```

```
LLDAP_ADMIN_PASSWORD=<пароль администратора каталога>
LLDAP_JWT_SECRET=<первая строка>
LLDAP_KEY_SEED=<вторая строка>
```

Запуск из каталога `source` вместе с остальным стеком:

```bash
docker compose --profile ldap up -d --build
```

Веб-интерфейс каталога: http://localhost:17170, вход `admin` и пароль из `LLDAP_ADMIN_PASSWORD`. Ядро ходит к каталогу внутри сети Docker по адресу `ldap:3890`.

## 2. Завести сотрудников в каталоге

В LLDAP:

1. «Groups» -> «Create a group»: `docssearch-users`
2. «Users» -> «Create a user»: логин `ivanov`, почта `ivanov@company.local`, имя «Иванов Иван», пароль. Без группы
3. Второй сотрудник `petrova` с почтой и паролем. На его странице в «Group memberships» добавить `docssearch-users`

Почта обязательна: по ней DocsSearch связывает доменную учётную запись со своей.

## 3. Включить LDAP в DocsSearch

Админ-панель -> «Настройки» -> «LDAP», включить «Вход через LDAP» и заполнить:

| Поле | Значение |
|---|---|
| Название | Корпоративный каталог (так будет подписана кнопка на экране входа) |
| Адрес сервера | `ldap` |
| Порт | `3890` |
| DN служебной учётной записи | `uid=admin,ou=people,dc=docssearch,dc=local` |
| Пароль служебной учётной записи | `LLDAP_ADMIN_PASSWORD` |
| Атрибут логина | `uid` |
| Атрибут почты | `mail` |
| База поиска | `ou=people,dc=docssearch,dc=local` |
| Фильтры поиска | пусто |
| TLS | выключен |

Если в `.env` задан свой `LLDAP_BASE_DN`, в DN и базе поиска вместо `dc=docssearch,dc=local` - он. «Сохранить».

Для Active Directory компании отличаются только значения: адрес контроллера домена, порт `389` или `636` с TLS, атрибут логина `sAMAccountName`, DN служебной учётной записи и база поиска из AD.

## 4. Сценарии для видео

Удобно записывать с двумя окнами браузера: обычное - администратор, приватное - сотрудник.

**Неверный пароль.** Экран входа -> «Продолжить через Корпоративный каталог» -> `ivanov` и неверный пароль. Ответ «Неверная почта, логин или пароль».

**Вход с подтверждением администратора.** `ivanov` и верный пароль. DocsSearch находит его в каталоге, проверяет пароль входом под его DN и создаёт учётную запись с ролью новых пользователей. При роли «ожидает» сотрудник видит «Учётная запись ожидает активации». Администратор: «Пользователи» -> `ivanov@company.local` (роль «Ожидает») -> в списке «Роль» выбрать «Сотрудник» -> «Сохранить». Сотрудник: «Проверить снова» -> открывается чат.

**Роль по группе каталога, без ручного подтверждения.**

1. Администратор: «Роли» -> «Сотрудник» -> «Группа каталога» `docssearch-users` -> «Сохранить»
2. «Настройки» -> «LDAP» -> включить «Роли по группам каталога», атрибут групп `memberOf` -> «Сохранить»
3. Сотрудник: вход как `petrova`. Группа совпала, роль «Сотрудник» назначена сразу, открывается чат без экрана ожидания
4. Администратор: «Пользователи» - у `petrova@company.local` роль «Сотрудник», подтверждать не пришлось

**Повторный вход.** Выйти и войти снова через каталог: та же учётная запись, история чатов на месте.

## 5. Убрать тестовый каталог

```bash
docker compose --profile ldap rm -sf ldap
docker volume rm docssearch_ldap-data
```

После этого в «Настройки» -> «LDAP» выключить вход через каталог или указать сервер компании.
